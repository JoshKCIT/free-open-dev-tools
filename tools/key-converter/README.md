# Key Pair Generator & Converter (PEM, JWK, OpenSSH)

Generate RSA, ECDSA and Ed25519 key pairs or convert keys between PEM, JWK and OpenSSH formats, with SSH fingerprints.

Part of [Free & Open Dev Tools](https://github.com/JoshKCIT/free-open-dev-tools). This folder is self-contained: it has its own
package file, tests, licence and documentation, and does not import anything from the rest of the repository.

## What it does

Makes key pairs in your browser with the browser's own Web Crypto generator and the audited @noble/curves and @noble/hashes libraries, and writes each one in the formats other software asks for, with the SHA256 and MD5 fingerprints that ssh-keygen prints. RSA keys are generated in a background worker so the page stays responsive, and the worker is stopped if it takes too long; Ed25519 and ECDSA keys take a few milliseconds and are made on the page itself. Nothing you generate is sent, stored or logged: the keys exist only in this page until you close it.

## Supported

- RSA key pairs of 2048, 3072 or 4096 bits with public exponent 65537, generated by Web Crypto in a background worker
- ECDSA key pairs on P-256, P-384 and P-521, generated by Web Crypto, with the public part recomputed by @noble/curves and compared
- Ed25519 key pairs made from 32 bytes of crypto.getRandomValues, with the arithmetic done by @noble/curves in every browser
- The private key as PKCS#8 (RFC 5958, with the ECDSA layout of RFC 5915 and the Ed25519 layout of RFC 8410) and the public key as SubjectPublicKeyInfo (RFC 5280), both as PEM
- The OpenSSH public key line (RFC 4253 section 6.6, RFC 5656 and RFC 8709) with an optional comment
- SSH fingerprints in both forms ssh-keygen prints: SHA256 (unpadded Base64) and MD5 (colon-separated hex)

## Limits

- Keys are made only by the browser's Web Crypto generator and crypto.getRandomValues; nothing else supplies randomness.
- Generating an RSA key runs in the background and stops after 60 seconds with a message; Cancel stops it at once.
- Private keys are shown in plain text so you can copy them; treat every private output as a secret and close the page when you are done.
- RSA sizes are limited to 2048, 3072 and 4096 bits with exponent 65537, ECDSA to P-256, P-384 and P-521, and no key is ever protected by a passphrase.
- This page makes keys; pasting a key to convert it is not offered yet.

## Ambiguous cases, and what this does about them

- RSA keys are made as RSASSA-PKCS1-v1_5 keys, and the key file does not record what a key is used for, so the same bytes work for signing, encryption and SSH
- An Ed25519 private key is its 32 byte seed (RFC 8032); the public key is computed from it, so the same seed always gives the same public key
- The comment is written after the key on the OpenSSH line and is not part of the key or its fingerprint

## Defined by

- [RFC 5958: Asymmetric Key Packages (PKCS#8)](https://www.rfc-editor.org/rfc/rfc5958)
- [RFC 5280: Internet X.509 Public Key Infrastructure Certificate and CRL Profile](https://www.rfc-editor.org/rfc/rfc5280)
- [RFC 8017: PKCS #1: RSA Cryptography Specifications Version 2.2](https://www.rfc-editor.org/rfc/rfc8017)
- [RFC 4253: The Secure Shell (SSH) Transport Layer Protocol](https://www.rfc-editor.org/rfc/rfc4253)
- [RFC 8410: Algorithm Identifiers for Ed25519, Ed448, X25519 and X448](https://www.rfc-editor.org/rfc/rfc8410)

```sh
npx degit JoshKCIT/free-open-dev-tools/tools/key-converter key-converter

```

## Install into a project

```sh
npm install @fodt/key-converter
```

This package is not published to npm. Copy the folder in, or add it as a workspace package, or depend on the
repository directly. The whole point is that you can vendor it: it is small enough to read.

## API

```ts
import { generateEd25519, generateRsa, keyFromGeneratedRsa, keyOutputs } from '@fodt/key-converter';

const ed = keyOutputs(generateEd25519(), { comment: 'me@example' });
// ed.blocks holds the PKCS#8 PEM, the SPKI PEM and the OpenSSH public line;
// ed.fingerprints is [['SHA256', 'SHA256:...'], ['MD5', 'MD5:...']].

const { pkcs8, spki } = await generateRsa(2048);
const rsa = keyOutputs(keyFromGeneratedRsa(pkcs8, spki), { comment: '' });
```

`generateRsa(bits)` asks Web Crypto for an RSASSA-PKCS1-v1_5 key (SHA-256, exponent 65537) and returns its PKCS#8 and SubjectPublicKeyInfo bytes; `bits` must be 2048, 3072 or 4096. `keyFromGeneratedRsa(pkcs8, spki)` reads both and checks they belong together. `generateEc(curve)` asks Web Crypto for an ECDSA key on P-256, P-384 or P-521 and returns the key model after the public point has been recomputed with @noble/curves and compared with the engine's. `generateEd25519()` takes 32 bytes from crypto.getRandomValues as the seed and returns the key model; @noble/curves asks the same generator for 16 more bytes of its own while it computes a public key. `keyOutputs(key, { comment })` writes every output from the package's own key model, never from the engine's own export, and returns blocks of text, fingerprints, facts and warnings. Every error is a `KeyConverterError`, `DerError` or `PemError` whose message names a position and the shape of the problem and never repeats any part of a key. `readDer`, `pemBlocks` and the Base64 and hex codecs are in their own files for reuse.

## Dependencies

- `@noble/curves` 2.4.0
- `@noble/hashes` 2.4.0

## Tests

```sh
npm test
```

Node's crypto (an OpenSSL-backed implementation independent of this package) and ssh-keygen 10.2p1 are the second opinions: RSA, ECDSA and Ed25519 keys made by Node are read from their PKCS#8 and SPKI bytes and written back byte for byte, the public lines and fingerprints of keys made by OpenSSL and ssh-keygen are the values ssh-keygen printed, and the RFC 8032 test 1 seed gives the published public key and the RFC 8410 layouts. The DER reader and PEM scanner are tested with hostile lengths, deep nesting and 500 KiB of BEGIN lines.
