# Key Pair Generator & Converter (PEM, JWK, OpenSSH)

Generate RSA, ECDSA and Ed25519 key pairs or convert keys between PEM, JWK and OpenSSH formats, with SSH fingerprints.

Part of [Free & Open Dev Tools](https://github.com/JoshKCIT/free-open-dev-tools). This folder is self-contained: it has its own
package file, tests, licence and documentation, and does not import anything from the rest of the repository.

## What it does

Makes key pairs in your browser with the browser's own Web Crypto generator and the audited @noble/curves and @noble/hashes libraries, or reads a key you paste in any common form, and writes it in every format other software asks for: PKCS#8, SubjectPublicKeyInfo, PKCS#1, SEC1, JWK, the OpenSSH private and public forms and RFC 4716, with the SHA256 and MD5 fingerprints ssh-keygen prints and the RFC 7638 JWK thumbprint. RSA keys are generated in a background worker so the page stays responsive, and the worker is stopped if it takes too long; Ed25519 and ECDSA keys take a few milliseconds and are made on the page itself. Nothing you generate or paste is sent, stored or logged: the keys exist only in this page until you close it.

## Supported

- RSA key pairs of 2048, 3072 or 4096 bits with public exponent 65537, generated by Web Crypto in a background worker
- ECDSA key pairs on P-256, P-384 and P-521, generated by Web Crypto, with the public part recomputed by @noble/curves and compared
- Ed25519 key pairs made from 32 bytes of crypto.getRandomValues, with the arithmetic done by @noble/curves in every browser
- Pasted keys in PKCS#8 (RFC 5958), SubjectPublicKeyInfo (RFC 5280), PKCS#1 (RFC 8017), SEC1 (RFC 5915), JWK (RFC 7517, 7518 and 8037, or the first key of a JWK set), the OpenSSH private key file and public key line, and RFC 4716 public key files
- The private key written as PKCS#8, PKCS#1 (RSA), SEC1 (ECDSA), JWK and the OpenSSH private key file with no passphrase, and the public key written as SubjectPublicKeyInfo, PKCS#1 (RSA), JWK, the OpenSSH line and an RFC 4716 file, each with a Copy and a Download button
- SSH fingerprints in both forms ssh-keygen prints, SHA256 (unpadded Base64) and MD5 (colon-separated hex), and the JWK SHA-256 thumbprint of RFC 7638
- RSA numbers dp, dq and qi worked out with BigInt when a key leaves them out, and every number checked: the modulus must be the product of the primes and the private exponent must undo the public one

## Limits

- Pastes of up to 64 KiB (65,536 characters) are read; a longer paste is refused before anything is parsed.
- RSA keys of up to 16,384 bits are converted; keys under 2,048 bits are shown with a warning. Generation offers 2,048, 3,072 and 4,096 bits with exponent 65537.
- Generating an RSA key runs in the background and stops after 60 seconds with a message; Cancel stops it at once.
- Passphrase-protected PEM and OpenSSH keys are refused, and outputs are never encrypted.
- Private keys are shown in plain text so you can copy or download them; treat every private output as a secret and close the page when you are done.
- Keys are made only by the browser's Web Crypto generator and crypto.getRandomValues; nothing else supplies randomness.
- Only RSA, ECDSA P-256, P-384 and P-521, and Ed25519 keys are supported; RSA-PSS keys restricted to one hash are refused.
- A JWK without the prime factors p and q cannot be converted, and a JWK set converts its first key only.

## Ambiguous cases, and what this does about them

- RSA keys are made as RSASSA-PKCS1-v1_5 keys, and the key file does not record what a key is used for, so the same bytes work for signing, encryption and SSH
- An Ed25519 private key is its 32 byte seed (RFC 8032); the public key is computed from it, so the same seed always gives the same public key
- The comment is written after the key on the OpenSSH line and in the RFC 4716 header and is not part of the key or its fingerprint; a pasted key that carries a comment keeps it unless the Comment field is filled in
- The four check bytes at the start of an OpenSSH private key are random, so the same key gives a different OpenSSH private file each time, and every one of them is the same key
- A JWK set holds several keys; only the first is converted, and the page says so
- Chromium and WebKit browsers add .txt to a download that has no file extension, so the OpenSSH private key may be saved as id_rsa.txt, id_ecdsa.txt or id_ed25519.txt; rename it to its plain name (Firefox keeps the name as written)

```sh
npm install @fodt/key-converter
```

This package is not published to npm. Copy the folder in, or add it as a workspace package, or depend on the
repository directly. The whole point is that you can vendor it: it is small enough to read.

## API

```ts
import { generateEd25519, generateRsa, keyFromGeneratedRsa, keyOutputs, readKeyInput } from '@fodt/key-converter';

const ed = keyOutputs(generateEd25519(), { comment: 'me@example' });
// ed.blocks holds the PKCS#8, SPKI, JWK, OpenSSH and RFC 4716 texts, each with an id, a label and a private flag;
// ed.fingerprints is [['SHA256', 'SHA256:...'], ['MD5', 'MD5:...'], ['JWK thumbprint', '...']].

const { pkcs8, spki } = await generateRsa(2048);
const rsa = keyOutputs(keyFromGeneratedRsa(pkcs8, spki), { comment: '' });

// Convert a pasted key (PEM, JWK, an OpenSSH line or an RFC 4716 file) into every format:
const read = readKeyInput(pastedText); // { key, source, comment?, warnings }
const converted = keyOutputs(read.key, { comment: read.comment ?? '' });
```

`generateRsa(bits)` asks Web Crypto for an RSASSA-PKCS1-v1_5 key (SHA-256, exponent 65537) and returns its PKCS#8 and SubjectPublicKeyInfo bytes; `bits` must be 2048, 3072 or 4096. `keyFromGeneratedRsa(pkcs8, spki)` reads both and checks they belong together. `generateEc(curve)` asks Web Crypto for an ECDSA key on P-256, P-384 or P-521 and returns the key model after the public point has been recomputed with @noble/curves and compared with the engine's. `generateEd25519()` takes 32 bytes from crypto.getRandomValues as the seed and returns the key model; @noble/curves asks the same generator for 16 more bytes of its own while it computes a public key. `readKeyInput(text)` reads a pasted key in any supported form (it refuses a paste over 65,536 characters before parsing) and returns the key model, a name for what it read, the comment it found and the warnings; every key it cannot read, a key protected by a passphrase, a certificate, an RSA-PSS key restricted to one hash and a public part that does not belong to its private part included, is a `KeyConverterError` with a plain sentence. `keyOutputs(key, { comment })` writes every output from the package's own key model, never from the engine's own export, and returns blocks of text (each with an id, a label, a private flag and, for JWK, the language json), fingerprints, facts and warnings. Every error is a `KeyConverterError`, `DerError` or `PemError` whose message names a position or the shape of the problem and never repeats any part of a key. `readDer`, `pemBlocks` and the Base64 and hex codecs are in their own files for reuse.

## Tests

```sh
npm test
```

Three second opinions that are not this package. Node's crypto (OpenSSL-backed) makes keys and reads every written form back: PKCS#8, SubjectPublicKeyInfo, PKCS#1, SEC1 and JWK are accepted by Node and re-exported as the same bytes, and JWK members equal Node's export for ten keys of each type. OpenSSL 3.5.5 wrote the PKCS#8, SubjectPublicKeyInfo, PKCS#1 and SEC1 bytes, and ssh-keygen 10.2p1 wrote the OpenSSH private files, the public lines, the RFC 4716 files and the SHA256 and MD5 prints for six keys, all recorded as literals by a recipe in test/fixtures (make-fixtures.sh) with their versions: the OpenSSH private writer reproduces each ssh-keygen file byte for byte given its check value and comment. The published vectors are RFC 8032 test 1, the Ed25519 JWK and thumbprint of RFC 8037 appendix A, the RSA example thumbprint of RFC 7638 section 3.1 and the RSA key of RFC 7515 appendix A.2. The DER reader and PEM scanner are tested with hostile lengths, deep nesting and 500 KiB of BEGIN lines, and pasted keys are fuzzed with a seeded generator.
